Esta página documenta todos os endpoints disponíveis para a entidade Atendimentos. O acesso a todas as rotas é restrito aos perfis GestaoGeral, Coordenacao e Psicologa. Usuários sem autenticação recebem 401 Unauthorized. Usuários autenticados com perfil não autorizado recebem 403 Forbidden.

GET /api/mentorias

Lista todas as mentorias com filtros opcionais.

Descrição

Retorna a lista de mentorias ordenada por data_mentoria DESC (mais recentes primeiro). Suporta filtros por jovem_id, status_mentoria, mentor e data_mentoria. O filtro status_mentoria é validado como enum — valor inválido retorna 400 Bad Request. O parâmetro jovem_id é convertido de string para número na camada Service antes do filtro SQL. Resultados vazios retornam 200 OK com array vazio.

Modelo de dados

Campo Tipo Obrigatório Observação
id INTEGER (PK) Auto Gerado automaticamente pelo banco.
atividades_id FK → atividades Sim Chave estrangeira obrigatória. Exclusão da atividade remove entregas vinculadas via CASCADE. FK inexistente retorna 500.
jovem_id FK → jovens Sim Chave estrangeira obrigatória. Exclusão do jovem remove entregas vinculadas via CASCADE. FK inexistente retorna 500.

Unique constraint: a combinação jovem_id + atividades_id é única — um jovem não pode submeter duas vezes para a mesma atividade. Violação retorna 409 Conflict. O erro de banco é encapsulado no Repository sem expor mensagens internas do PostgreSQL.

Atualização parcial restrita: apenas status, nota, data_entrega e observacao são atualizáveis. atividades_id e jovem_id são imutáveis após criação, preservando o vínculo original da entrega.

Retorna a lista de jovens ativos classificados como em risco de evasão.

Descrição

A query busca todos os jovens com ativo = true e calcula, para cada um, três métricas derivadas dos últimos 30 dias: percentual de frequência (presencial ou gravação), dias desde a última interação registrada e quantidade de atividades com status Atrasada. Jovens sem nenhum registro de frequência recebem dias_sem_interacao: 999 (valor sentinela) e frequencia_ultimos_30_dias: 0.

Após a query, o Service aplica a função calcularRiscoEvasao a cada jovem e filtra apenas os que possuem em_risco: true. Um jovem é classificado em risco quando atende ao menos um dos critérios abaixo:

Fator de risco Critério Label no payload
Baixa frequência frequencia_ultimos_30_dias < 75% sem_interacao
Atividades atrasadas atividades_em_atraso >= 2 atividades_atrasadas
Queda acentuada de frequência queda_frequencia_pp >= 7 queda_acentuada

O nível de risco é determinado pelo número de fatores ativos: 1 fator → nivel: "medio"; 2 ou mais fatores → nivel: "alto". Jovens sem fator algum não aparecem na lista.
