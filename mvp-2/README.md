## 📜 Descrição

O **Pulsar** é um sistema web desenvolvido para a ONG **Pulse Mais**, voltado à gestão, ao acompanhamento e à análise da trajetória dos jovens atendidos pela organização. A proposta central da plataforma é funcionar como uma **fonte única de verdade**, permitindo que diferentes áreas da Pulse Mais acompanhem o desenvolvimento acadêmico, profissional, emocional e social dos alunos de maneira integrada, segura e eficiente. O sistema também permite que os próprios alunos cadastrem e acompanhem seus dados, seu progresso e as oportunidades disponíveis.

A plataforma foi pensada para atender **diferentes perfis de usuários**, cada um com permissões e funcionalidades específicas. Entre os principais atores estão a coordenação de projetos, responsável pelo acompanhamento geral dos alunos e programas; a gestão estratégica, que utiliza indicadores e relatórios para tomada de decisão; os próprios alunos, que visualizam seu progresso e atualizam informações pessoais; e os mentores, que acompanham o desenvolvimento dos mentorados ao longo da jornada.

A arquitetura segue o padrão em camadas **Controller → Service → Repository**, separando responsabilidades para tornar o projeto mais organizado, escalável e de fácil manutenção. A camada *Controller* recebe as requisições, a camada *Service* aplica as regras de negócio, a camada *Repository* comunica-se com o banco de dados e a camada *Model* representa as entidades do sistema. O projeto utiliza ainda *middlewares* de autenticação (JWT) e autorização baseada em papéis (*role-based*), garantindo que cada usuário visualize apenas as informações permitidas pelo seu perfil.

Entre as principais funcionalidades estão o cadastro e gerenciamento de alunos, o registro de frequência em aulas e eventos, o acompanhamento de mentorias, o histórico de participação em atividades, a gestão de cursos e bolsas e a geração de indicadores e dashboards administrativos. O sistema também oferece segmentação e filtros avançados, permitindo localizar rapidamente informações específicas sobre estudantes, programas ou indicadores institucionais, com forte foco na **análise de impacto social** (retenção, evolução acadêmica, empregabilidade e engajamento).

No backend foram utilizadas tecnologias como **Node.js**, **Express** e **PostgreSQL (Supabase)**. O projeto adota práticas de qualidade de software — organização modular, separação de responsabilidades e testes automatizados com **Jest** — cobrindo casos de sucesso, validação de regras de negócio, tratamento de payloads inválidos e persistência no banco.

## 🛠️ Tecnologias

| Camada | Tecnologia |
|--------|-----------|
| Runtime | Node.js |

## 💻 Como executar o código (passo a passo)

Esta seção foi escrita para que **qualquer pessoa, mesmo sem experiência com programação**, consiga rodar a aplicação na própria máquina. Basta seguir os passos na ordem.

> ℹ️ A aplicação tem duas partes que precisam funcionar juntas: o **servidor** (o programa Node.js que você vai iniciar) e o **banco de dados PostgreSQL** (onde as informações ficam guardadas). Os passos abaixo cobrem as duas.

### Passo 1 — Instalar o Node.js

O Node.js é o programa que executa o código do servidor.

1. Acesse o site oficial: [https://nodejs.org/pt-br](https://nodejs.org/pt-br)
2. Baixe a versão marcada como **LTS** (versão estável recomendada).
3. Execute o instalador e avance mantendo todas as opções padrão até concluir.
4. Para confirmar a instalação, abra o terminal (no Windows, pesquise por **PowerShell** ou **cmd** no menu Iniciar) e digite:
   ```sh
   node --version
   ```
   Se aparecer algo como `v20.x.x`, deu certo.

### Passo 2 — Instalar o Git

O Git é a ferramenta usada para baixar (clonar) o projeto.

1. Acesse: [https://git-scm.com/downloads](https://git-scm.com/downloads)
2. Baixe o instalador do seu sistema operacional e execute-o, mantendo as opções padrão.
3. Confirme com:
   ```sh
   git --version
   ```

### Passo 3 — Instalar o Visual Studio Code (recomendado)

O VS Code é um editor gratuito da Microsoft que facilita abrir o projeto e usar o terminal.

1. Acesse: [https://code.visualstudio.com](https://code.visualstudio.com)
2. Baixe, instale e abra o programa.

### Passo 4 — Instalar o PostgreSQL

O PostgreSQL é o banco de dados onde a aplicação guarda as informações.

1. Acesse: [https://www.postgresql.org/download/](https://www.postgresql.org/download/)
2. Baixe o instalador do seu sistema, execute-o e siga as instruções.
3. Durante a instalação, **anote a senha** que você definir para o usuário `postgres` — ela será usada no Passo 7.

> 💡 Alternativa sem instalar nada: o projeto também funciona com um banco PostgreSQL na nuvem, como o [Supabase](https://supabase.com). Nesse caso, basta ter a *string de conexão* (URL) do banco, que será usada no Passo 7.

### Passo 5 — Clonar o repositório

Clonar significa baixar uma cópia completa do projeto para o seu computador.

1. Abra o terminal (no VS Code, use o menu **Terminal → Novo Terminal**).
2. Navegue até a pasta onde quer salvar o projeto. Por exemplo, para a Área de Trabalho:
   ```sh
   cd Desktop
   ```
3. Clone o repositório:
   ```sh
   git clone https://git.inteli.edu.br/graduacao/2026-1b/t29/g02.git
   ```
4. Entre na pasta criada:
   ```sh
   cd g02
   ```

> 🔁 **Método alternativo (sem Git):** no GitLab, clique em **Code → Download ZIP**, extraia o arquivo em uma pasta e abra essa pasta no VS Code.

### Passo 6 — Instalar as dependências

Ainda no terminal, dentro da pasta do projeto, execute:

```sh
npm install
```

Esse comando lê o arquivo `package.json` e baixa automaticamente todas as bibliotecas necessárias (Express, pg, bcrypt, jsonwebtoken etc.). Pode levar alguns minutos na primeira vez.

> ⚠️ O `npm install` instala apenas as bibliotecas do Node. Ele **não** prepara o banco de dados. Por isso ainda faltam o Passo 7 (configurar o `.env`), o Passo 8 (criar as tabelas) e o Passo 9 (criar usuários de teste) antes de a aplicação funcionar de verdade.

### Passo 7 — Configurar as variáveis de ambiente (.env)

As configurações sensíveis (como o acesso ao banco) ficam em um arquivo chamado `.env`, que você cria a partir do modelo `.env.example`.

1. Crie a cópia do modelo:
   - **Windows (PowerShell/cmd):**
     ```sh
     copy .env.example .env
     ```
   - **Linux/macOS:**
     ```sh
     cp .env.example .env
     ```
2. Abra o arquivo `.env` no VS Code e ajuste os valores conforme o seu ambiente:
   ```env
   # Servidor
   PORT=3000

   # Banco de dados PostgreSQL
   DATABASE_URL=postgresql://usuario:senha@localhost:5432/nome_do_banco

   # Sessão
   SESSION_SECRET=troque_por_uma_string_longa_e_aleatoria

   # Bcrypt — custo de hash (mínimo 10 conforme RNF-SEG-01)
   BCRYPT_COST=10

   # JWT
   JWT_SECRET=troque_por_uma_string_longa_e_aleatoria
   JWT_EXPIRES_IN=24h
   ```
   - **PORT**: porta em que o servidor vai rodar. Se não mudar, será a `3000`.
   - **DATABASE_URL**: endereço de conexão com o PostgreSQL. Troque `usuario`, `senha` e `nome_do_banco` pelos dados definidos no Passo 4 (ou cole a URL do Supabase).
   - **SESSION_SECRET**: chave usada para proteger os dados de sessão. Use um texto longo e aleatório.
   - **BCRYPT_COST**: custo de processamento para criptografar senhas. O padrão recomendado é `10`.
   - **JWT_SECRET**: chave secreta usada para assinar os tokens de login (JWT). Use um texto longo e aleatório.
   - **JWT_EXPIRES_IN**: tempo de validade do token de login (ex.: `24h`).

> 🔒 O arquivo `.env` **nunca** deve ser enviado ao repositório, pois contém dados sensíveis. Apenas o `.env.example` é versionado.

### Passo 8 — Primeira execução

Com o `.env` configurado, o banco ainda está **vazio**. O Pulsar suporta dois modos
de inicialização. Escolha **um**.

#### Modo Produção (recomendado para implantação real)

Sobe o sistema **sem nenhum dado de negócio** (zero jovens, zero programas, zero
eventos). Todos os cadastros são feitos depois, pela interface, pelo gestor.

1. Aplicar as migrations (cria as tabelas):
   ```sh
   npm run migrate
   ```
   O script aplica, em ordem, todos os arquivos de `src/database/migrations/`. É
   seguro rodar mais de uma vez — migrations já aplicadas são puladas. Ao final,
   aparece `✅ X migration(s) aplicada(s) com sucesso.`

2. Criar o **gestor inicial** (bootstrap de acesso):
   ```sh
   npm run setup:gestor
   ```
   Credenciais padrão geradas (perfil `GestaoGeral`):
   - **E-mail:** `ana.gestao@pulse.org.br`
   - **Senha:** `senha123`

   O script é **idempotente**: se já existir um usuário com esse e-mail, ele
   apenas atualiza a senha/perfil em vez de duplicar. Você pode definir nome,
   e-mail e senha próprios como argumentos:
   ```sh
   npm run setup:gestor -- "Ana Gestora" "ana@pulse.org.br" "minhasenha"
   ```

3. Iniciar a aplicação:
   ```sh
   npm start
   ```

4. Abrir no navegador: `http://localhost:3000/pages/login.html` e entrar
   com a credencial criada no passo 2.

> ❗ Se aparecer um erro de conexão na migration, quase sempre é a `DATABASE_URL`
> do `.env` incorreta. Revise o Passo 7. Para Postgres local sem SSL, basta a URL
> normal; para Supabase, o SSL é detectado automaticamente.

#### Modo Demonstração (apenas desenvolvimento)

Inclui carga de **dados fictícios** para visualizar o sistema povoado.
**Não usar em produção.**

1. Aplicar as migrations:
   ```sh
   npm run migrate
   ```
2. Carregar os dados de demonstração:
   ```sh
   npm run seed:demo
   ```
3. Criar o gestor inicial (os usuários do seed têm senha fictícia e não logam):
   ```sh
   npm run setup:gestor
   ```
   Opcionalmente, crie também mentor e aluno de teste:
   ```sh
   npm run setup:mentor
   npm run setup:aluno
   ```
4. Iniciar a aplicação:
   ```sh
   npm start
   ```

### Passo 9 (opcional) — Modo de desenvolvimento

Para que o servidor reinicie sozinho a cada alteração no código (útil para quem vai programar), use:

```sh
npm run dev
```

### Passo 10 (opcional) — Executar os testes automatizados

O projeto usa **Jest**. Para rodar toda a bateria de testes:

```sh
npm test
```

Outros comandos úteis de teste:

```sh
npm run test:watch              # roda os testes em modo observação
npm run test:only-unit          # apenas testes de unidade (services)
npm run test:only-integration   # apenas testes de integração (controllers)
```

Os testes verificam regras de negócio, validações, persistência no banco e o funcionamento dos endpoints principais da API.
